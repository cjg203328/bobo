# 零基础直达 · justailab 核心能力机制拆解与 bobo 落地设计

> 日期：2026-10-22
> 定位：本文是《justailab兼容改造-差距分析与开发计划》的**产品原则层补充**，其 §五 的 P0-P4 顺序按本文北极星重排（见 §五）
> 用户原话：「他这个平台最好的能力是适配零基础客户，就是可以通过 skill 或者对话的能力直接让 agent 生成需要的产物」

---

## 〇、先把判断 sharpen：不是「skill 或对话」，是「对话是唯一入口，skill 是隐形基础设施」

用户说的「通过 skill 或者对话」是合理的使用者视角，但 justailab 的产品真相更激进一层：

> **零基础用户全程不需要知道 skill 的存在。** 他们看到的只有：一个对话框、一排场景卡片、一句「一句话搞定你的内容需求」。技能是服务端的路由目标，提示词是服务端的组装材料，模型是服务端的选择结果——**用户端零概念、零配置、零提示词工程**。

技能市场（231 个、使用量、付费墙）服务的是**创作者供给侧**；对零基础的需求侧用户，市场只以「本周精选 + 使用量社会证明」的形态露出。**这条「需求侧零摩擦直达链」才是 justailab 的产品本体**，市场/支付/裂变都是它的商业化外延。

---

## 一、机制拆解：justailab 的「零摩擦直达链」六层（全有代码/数据证据）

```
① 入口层    对话框 + 场景卡片（本周精选带使用量）+ 分类筛选
              —— 不是空文档、不是空画布、不是模型选择器
② 表达层    一句话（自然语言）或 一张表（marketing_form 服务端下发表单）
              —— 用户从不写提示词；表单填的是「IP 领域/目标受众/人设风格」这种业务字段
③ 路由层    description 触发语义（「当你提供 X 时，调用该技能…」）→ 服务端匹配
              —— 226/230 技能默认 on_demand（自动）；手动挂载上限 2（辅助路径）
④ 组装层    客户端只传 skill_id；服务端取 prompt_content + references 注入 LLM 上下文
              —— 提示词资产对用户不可见（market_prompt_visible 全量 false）
⑤ 产出层    文案 + 封面 + 配图 一次生成（成品而非半成品）
              —— 平台预设内建：小红书 3:4、抖音 9:16、发布目标直选；实测「30 秒出完整图文」
⑥ 沉淀层    好对话 → 存为技能（create_from_conversation）；爆款链接 → 一键复刻；
              常用技能 → 常驻菜单（默认已常驻 8 个官方技能）
              —— 用得越多，个人技能库越强，迁移成本越高
```

**关键佐证**（三份分析文档）：
- 教程原文：「选好技能后，回到新对话界面，用自然语言说出需求…稍等片刻，小加同学会一次性输出。关键是，文案和配图是一起生成的」
- 动态实测：231 技能中 85% 官方自营——**用户无感于市场结构，只感受到「什么都能做」**
- 深扒实证：`chat_stream` payload 无任何提示词正文；`req_key` 模型路由在模板 schema 里——**用户端零模型概念**

## 二、摩擦审计：bobo 现状逐层对照

| 层 | justailab | bobo 现状（代码证据） | 摩擦判定 |
|---|---|---|---|
| ① 入口 | 对话框 + 场景卡 | 画布优先（BeefTV 基因：home-dashboard → canvas）；创作台有「精选灵感」卡片但**硬编码短剧向**（雨夜霓虹/港风天台，非电商） | ⚠️ 空画布恐惧 + 灵感与目标场景错位 |
| ② 表达 | 一句话 or 表单 | 助手对话框 ✅；**场景表单缺失**（marketing_form 对应物 0 命中） | ❌ 缺一半 |
| ③ 路由 | description 自动匹配 | **skill_load 工具 + 目录广告 + 系统指令已实现**（`durable-session-owner.mjs:170`） | ✅ **已超越**（justailab 是服务端匹配，bobo 是模型自主 skill_load） |
| ④ 组装 | 服务端注入 | **Pin 三角 + Scope 门禁 + linked-context 按需加载**（4 技能/32k 字符） | ✅ **已超越** |
| ⑤ 产出 | 图文一次生成 + 平台预设 | 视频链路通（configure→render→task）；**单图断**（无 media.generate op）；**无平台预设**；**无模板引擎** | ❌ **最大断点** |
| ⑥ 沉淀 | 对话→技能/复刻/常驻 | **create_from_conversation 缺失**；常驻概念有（Pin 跨轮有效） | ❌ 缺一项 |

**审计结论**：bobo 在 ③④ 两层（路由与组装）已经比 justailab 更深，断点集中在 **⑤ 产出层**——这正是「零基础直达」的最后一公里。**计划资源应向 ⑤ 倾斜。**

## 三、bobo 要继承的五条设计原则

1. **隐形技能**：默认路径用户看不到 skill 选择器（`SkillRuntimePicker` 降级为「高级」折叠项）；技能是后端路由目标，不是前端操作对象。
2. **一句话或一张表**：每个场景提供两种入口——自然语言直说（走 skill_load 自动路由）或场景表单（业务字段填空，系统拼 prompt）。**禁止在任何默认路径要求用户写提示词。**
3. **成品直出**：输出必须是可发布物料（文案+封面+配图/视频一套），不是半成品；平台预设（比例/语言/风格）内建于模板，高级参数折叠。
4. **自动决策**：技能选择、模型选择、比例、风格全部系统默认；用户可覆盖，但覆盖不是必经之路。
5. **越用越强**：对话一键存技能（create_from_conversation）、爆款链接复刻、常用技能常驻——沉淀机制让零基础用户随时间变成「技能拥有者」而不自知。

## 四、北极星指标

| 指标 | 定义 | justailab 基准 | bobo 目标 |
|---|---|---|---|
| **主：首次成品时间** | 新用户从打开到拿到第一个可发布物料 | ~30 秒（教程实测口径） | **< 2 分钟**（含首次安装/配置） |
| 副：一句话命中率 | 自然语言请求被 skill_load 正确路由的比例 | 226/230 on_demand | 种子技能全覆盖常见电商意图 |
| 副：成品直出率 | 产出无需二次手动修改即可发布的比例 | 「直接可发布到小红书/公众号/美团」 | 首批场景 ≥ 70% |

**每一期都必须能回答「它让首次成品时间缩短了多少」**，答不上来的期降级或后置。

## 五、计划重排（北极星优先，取代差距分析 §五 的顺序）

原顺序（市场字段 → AI 生产线 → 单图直出 → 模板引擎 → 打磨）服务的是「平台完整度」；新顺序服务「直达链」。工期总量不变（19.5 天），只改先后：

### P0' · 直达链最小闭环（6 天）—— 最高优先

| # | 任务 | 服务的指标 |
|---|---|---|
| 0.1 | **场景面板**：`scene-templates.json` + 创作台「场景」Tab（5 个电商表单：商品种草/爆款封面/直播口播/详情页/促销清单） | 首次成品时间（填表路径） |
| 0.2 | **`media.generate` op**：prompt/ratio/refs/model → generation 包出图 → asset 落库 + 回合流 asset 事件 | 首次成品时间（出图断点） |
| 0.3 | 画布绑定闭环：media.generate → canvas_node_bind_asset | 成品落画布 |
| 0.4 | 3 个最小种子技能（商品种草/爆款封面/口播稿，三段式规范） | 一句话命中率 |
| 0.5 | 创作台灵感卡片电商化替换（下架短剧向硬编码，改电商向 + 接技能数据） | 入口摩擦 |

**验收**：零基础用户打开 → 选「商品种草图文」场景 → 填 5 个字段（或直接说一句话）→ **一次拿到文案+封面+3 配图，落画布，可保存发布**。全程未碰模型/技能/提示词概念。

### P1' · 模板引擎 + 平台预设（4 天）

| # | 任务 | 服务的指标 |
|---|---|---|
| 1.1 | IllustrationTemplate 模型（schema + req_key + propertiesJSONSchema）+ 前端表单渲染 | 成品直出率 |
| 1.2 | `illustration.render` agent 工具（模型按模板填参直出） | 一句话命中率 |
| 1.3 | 平台预设：小红书 3:4 / 拼多多 1:1 / 抖音 9:16 / TikTok en | 成品直出率 |
| 1.4 | 5 个配图种子模板 | 成品直出率 |

**验收**：agent 说「按商品卡模板出图」自动填参直出；平台切换一键改比例/语言。

### P2' · AI 生产线（4 天）

| # | 任务 | 服务的指标 |
|---|---|---|
| 2.1 | `ai_draft`：想法/链接/图 → LLM 生成 SKILL.md 三件套 → 草稿态 → 修订发布 | 沉淀（越用越强） |
| 2.2 | `create_from_conversation`：回合历史 → 提炼为技能 | 沉淀 |
| 2.3 | description 三段式弱校验 + 「自动触发」徽标 | 一句话命中率 |
| 2.4 | 剩余 9 个电商种子技能（含 2 个 TikTok 英文版） | 一句话命中率 |
| 2.5 | 加分项：爆款链接复刻（贴链接 → 抓内容 → 按模板重生成） | justailab 招牌功能对齐 |

**验收**：「我想做个 XX 技能」→ AI 起草 → 发布 → 被 skill_load 命中；一回合好对话 → 一键存技能。

### P3' · 市场层（2.5 天）—— 后置：服务供给侧，不服务直达

运营字段（usage_count/last_used_at/is_featured/author_type）+ skill_load 埋点 + import_folder 多文件导入 + 分享导入 + 「最多使用」排序。

### P4' · 打磨发布（3 天）

暗色精修、卡片密度、4 字 label、e2e 全链回归（创建→发布→路由→直出→用量回收）、《零基础创作指南》。

## 六、风险与边界

1. **P0' 的 media.generate 权限**：出图耗真实额度，必须接入回合预算与权限模式（operation-bridge 框架已有，勿绕开）——设计上即「full-access 模式才允许非只读执行」。
2. **场景面板的数据形态**：justailab 的 marketing_form 是服务端下发（可热更新）；bobo 本地版用 JSON 配置文件达到同等灵活（改配置即生效，无需发版）——**保持这个等价性，不要硬编码进前端**。
3. **「隐形技能」与现有 UI 的冲突**：`SkillRuntimePicker`（多选技能）在创作台已存在——不停用，降级为高级模式；默认路径只暴露场景与对话框。
4. **30 秒基准的口径**：justailab 的 30 秒指登录后单次生成，不含首次配置；bobo 的 2 分钟目标含 Gemini Key 首次配置——**需在 P0' 验收时实测校准**。
5. 本文所有 justailab 结论来自未登录态外部观察（既有边界声明）；bobo 结论全部有代码位置索引（见差距分析文档附录）。
